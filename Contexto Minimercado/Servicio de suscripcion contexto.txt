  2. Middleware de Validación (El Núcleo del Bloqueo)
  ARCHIVO: MiniMercado/Middleware/TenantValidationMiddleware.cs

  MOTIVO: Es el componente responsable de interceptar cada petición y validar si el Tenant tiene permiso para operar.

    2 {

    4     // 🔹 Ignorar rutas públicas (Login, Bloqueado, Recursos estáticos)
    5     if (path != null && (path.StartsWith("/Account/Login") || path.StartsWith("/Cuenta/Bloqueado") || ...))
    6     {
    7         await _next(context);
    8         return;
    9     }

   11     if (context.User.Identity.IsAuthenticated)

   15         {
   16             // 1. Validar si el tenant está inactivo (Cierra sesión)

   19                 await signInManager.SignOutAsync();
   20                 context.Response.Redirect("/Tenant/Desactivado");
   21                 return;
   22             }

   24             // 2. Validar bloqueo manual o vencimiento automático
   25             bool estaVencido = tenant.FechaVencimiento.HasValue && tenant.FechaVencimiento.Value < DateTime.Now;
   26             if (tenant.Bloqueado || estaVencido)
   27             {
   28                 context.Response.Redirect("/Cuenta/Bloqueado");
   29                 return;
   30             }
   31
   32             // 🔔 3. Notificación de vencimiento próximo (7 días antes)
   33             if (tenant.FechaVencimiento.HasValue)
   34             {
   35                 var diasRestantes = (tenant.FechaVencimiento.Value - DateTime.Now).TotalDays;
   36                 if (diasRestantes > 0 && diasRestantes <= 7)
   37                 {
   38                     // Genera notificación interna una vez cada 24hs
   39                     await notificacionService.CrearNotificacion(
   40                         "Suscripción por vencer",
   41                         $"Tu suscripción vence en {Math.Ceiling(diasRestantes)} días...",
   42                         "Pago"
   43                     );
   44                 }
   45             }
   46         }
   47     }
   48     await _next(context);
   49 }

 Informe de Auditoría Profunda: Ciclo de Vida de Suscripciones y Bloqueos

  Este informe detalla el flujo completo de las propiedades críticas de membresía y los mecanismos de control de acceso
  en MiniMercado SaaS.

  2. Análisis del Ciclo de Vida

  A. Creación Inicial
  La FechaVencimiento y FechaProximoPago se crean inicialmente como null cuando se registra un nuevo comercio a través
  de TenantsController.Index. El estado inicial es PendientePago.

  B. Actualización y Extensión (Pagos)
  La extensión de la suscripción ocurre exclusivamente en SuscripcionService.RegistrarPagoAsync. La lógica permite la
  acumulación: si el usuario paga antes de vencer, los meses se suman a la fecha futura; si ya venció, se suman desde
  "hoy".

  C. Lógica de Bloqueo y Vencimiento
   * Vencimiento Automático: Se calcula comparando FechaVencimiento < DateTime.Now. Es evaluado en cada petición por el
     Middleware.
   * Bloqueo Manual: Controlado por la propiedad Bloqueado. Un AdminGlobal puede activarlo en cualquier momento.
   * Período de Gracia: No existe. El sistema bloquea el acceso en el segundo exacto en que la fecha de vencimiento es
     superada.
   * Configuración de Alertas: Existe un aviso hardcodeado de 7 días en el Middleware que genera una notificación
     interna.

  D. Tareas Automáticas
  No existen procesos en segundo plano (Workers, Hangfire o Cron Jobs). Toda la validación de estados y envíos de
  notificaciones de vencimiento se disparan "on-demand" cuando el usuario navega por el sistema, procesadas por el
  TenantValidationMiddleware.

 Estado Actual del Módulo de Suscripciones SaaS - MiniMercado - 15/6/2025

  Este documento detalla la implementación técnica, lógica de negocio y mecanismos de control del módulo de
  suscripciones del sistema MiniMercado SaaS.

  ---

  1. Objetivo del Módulo
  El objetivo principal es gestionar el ciclo de vida comercial de cada comercio (Tenant) dentro de la plataforma. El
  sistema garantiza el cobro del servicio mediante un flujo progresivo de advertencias, un período de gracia y,
  finalmente, la restricción total del acceso para garantizar la rentabilidad del SaaS.

  ---

  2. Entidades Involucradas

  Tenant
   * Archivo: MiniMercado/Models/Tenant.cs
   * Propiedades Relevantes:
       * Activo (bool): Control administrativo manual para habilitar/deshabilitar el comercio.
       * Bloqueado (bool): Flag manual de suspensión inmediata.
       * FechaVencimiento (DateTime?): Fecha límite de uso del servicio.
       * FechaProximoPago (DateTime?): Sincronizada con el vencimiento para cálculos de extensión.
       * EstadoSuscripcion (Enum): Activa, PendientePago, Vencida, Suspendida.

  Notificacion
   * Archivo: MiniMercado/Models/Notificacion.cs
   * Propiedades Relevantes:
       * Tipo: Identificador "Pago" para alertas de suscripción.
       * Leida: Estado de visualización por el usuario.
       * Url: Link hacia /Configuracion/Suscripcion.

  ---

  3. Flujo Completo de Negocio

   1. Tenant Activo: El comercio opera con normalidad.
   2. Aviso Preventivo (7 días antes): El sistema genera una Notificación Interna (campana) visible en el dashboard.
   3. Advertencia Visual (5 días antes): Se activa un Banner Naranja persistente (pero descartable por 24hs) en la parte
      superior.
   4. Día de Vencimiento: El banner cambia a Rojo y el mensaje indica que la suscripción ha expirado.
   5. Período de Gracia (Día 1 a 5 post-vencimiento): Se mantiene el acceso al sistema pero con el Banner Rojo
      inamovible (descartable por 24hs).
   6. Bloqueo Automático (Día 6 post-vencimiento): El sistema impide la navegación y redirige forzosamente a la pantalla
      de bloqueo.
   7. Pantalla de Bloqueo: Interfaz aislada sin menús. Ofrece contacto vía WhatsApp y botón de Logout.
   8. Reactivación: Tras el registro manual de un pago por el administrador global, se extiende la fecha y se recupera
      el acceso.

  ---

  4. Middleware: TenantValidationMiddleware.cs

  Es el motor de seguridad del sistema. Se ejecuta en cada solicitud HTTP.

   * Exclusiones: Ignora rutas de login, recursos estáticos (/css, /js, /lib), la ruta de error y la propia ruta
     /Cuenta/Bloqueado para evitar bucles infinitos.
   * Validación de Tenant Activo: Si Activo == false, cierra la sesión del usuario y redirige a /Tenant/Desactivado.
   * Validación de Bloqueo:
       * Manual: Si Bloqueado == true, redirige a /Cuenta/Bloqueado.
       * Automático: Calcula diasVencido. Si la diferencia entre hoy y FechaVencimiento es mayor a 5 días, redirige a
         /Cuenta/Bloqueado.

   1 // Fragmento de validación automática
   2 var diasVencido = (DateTime.Now.Date - tenant.FechaVencimiento.Value.Date).Days;
   3 if (diasVencido > 5) {
   4     context.Response.Redirect("/Cuenta/Bloqueado");
   5     return;
   6 }

  ---

  5. Sistema de Notificaciones

  Gestionado por NotificacionService.cs.
   * Creación: Se disparan 7 días antes del vencimiento.
   * Frecuencia: Utiliza un sistema de caché de 24 horas (notif_pago_{tenantId}) para evitar que el middleware cree
     múltiples notificaciones idénticas en la base de datos durante una misma jornada.
   * Almacenamiento: Persistente en la tabla Notificaciones.

  ---

  6. Sistema de Banners (_Layout.cshtml)

  Implementado en el layout principal mediante Razor + JavaScript.
   * Banner Naranja: diasRestantes > 0 && <= 5.
   * Banner Rojo: diasRestantes <= 0 && >= -5.
   * Botón Cerrar: Utiliza un botón btn-close-white.
   * Persistencia (localStorage): Al cerrar, se guarda la clave bannerSuscripcionOculto_YYYY-MM-DD. Al cambiar la fecha
     del sistema, el banner vuelve a aparecer automáticamente.

  ---

  7. Sistema de Bloqueo

  Bloqueo Manual
   * Activado por la propiedad tenant.Bloqueado.
   * Gestionado por el AdminGlobalController.cs a través del método ToggleBloqueo.
   * Impacto inmediato (limpia el caché del tenant).

  Bloqueo Automático
   * Lógica: (Hoy - FechaVencimiento) > 5 días.
   * El período de gracia es de 5 días exactos. El bloqueo ocurre al inicio del 6to día de vencimiento.

  ---

  8. Pantalla de Bloqueado

   * Controlador: CuentaController.cs con la acción Bloqueado().
   * Seguridad: Marcada con [AllowAnonymous] y excluida del Middleware.
   * Interfaz: Views/Cuenta/Bloqueado.cshtml.
       * Layout = null: No carga estilos ni scripts del sistema.
       * WhatsApp: Botón configurado dinámicamente con el número de soporte y un mensaje pre-armado.
       * Logout: Única acción de navegación permitida dentro del sistema.

  11. Riesgos Conocidos

   * Zona Horaria: El sistema utiliza DateTime.Now del servidor. Diferencias entre el servidor y el cliente podrían
     causar que el banner aparezca o desaparezca unas horas antes/después.
   * Caché: El middleware cachea el Tenant por 10-30 minutos. Un desbloqueo manual puede tardar ese tiempo en impactar
     si no se limpia el caché explícitamente (solucionado en ToggleBloqueo pero pendiente en otros puntos).
